# Project instructions / دستور ادامه پروژه
قبل از هر تغییر README و docs/schema-and-relations.md و docs/costing-rules.md و docs/validation-log.md و docs/roadmap.md را بخوان.
- کاربر انتظار دارد هر یافته جدید در همین مخزن ثبت شود. بعد از دریافت نتیجه واقعی، مستندات مرتبط و وضعیت roadmap را به‌روز کن. تاریخ، شناسه مرحله، دامنه، فیلتر، grain، کنترل، نتیجه، استثنا و وضعیت تایید را ثبت کن.
- بین مشاهده واقعی، فرضیه، سیاست پیشنهادی و نتیجه تست نشده تفکیک کن. خطاهای SQL و نسخه اصلاحی را نیز ثبت کن. داده‌های خام، شناسه اسناد واقعی، مبالغ تجاری، نام مشتری/تامین‌کننده و اسرار اتصال را در مخزن عمومی قرار نده.
- منبع ERP فقط SELECT و CTE؛ هیچ temp table، DDL/DML، SP، NOLOCK. MAXDOP 1، تست تشخیصی بیشتر از 60 ثانیه متوقف شود. خروجی خلاصه <=100؛ استثناهای هدفمند ترجیحاً <=20. از بازنویسی همه مراحل قبلی در یک CTE پیچیده بپرهیز.
- روابط کاندید را قطعی نخوان. مقدار و هزینه نامعلوم NULL؛ قیمت تخمینی برچسب‌دار. کلیدها پیش از aggregate یکتا؛ کنترل بقای مقدار در تمام روابط مرتبط، نه فقط جامعه هدف.
- پیش از ادامه، نقطه توقف roadmap را بررسی کن. ثبت موفق در GitHub را فقط پس از نتیجه موفق API اعلام کن. در صورت نبود دسترسی، به کاربر اطلاع بده.
