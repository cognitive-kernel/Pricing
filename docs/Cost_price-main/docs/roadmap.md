## معماری هدف
منبع ERP فقط SELECT؛ استخراج‌های کوچک مستقل و قابل تست (گردش، قیمت رسمی، خرید، فروش، برگشت، روابط). روی سرور گزارش‌گیری یا Python ذخیره و اتصال داده، حل گراف وابستگی و موتور FIFO صف/لایه. هزینه محاسبه O(n) تقریبی برای صف‌های مرتب، بدون cross join کل خریدها با فروش‌ها؛ استثناهای مرجعی و گراف جدا. نگهداری تاریخچه تخصیص و checkpoint، بازپردازش از اولین رویداد اصلاح‌شده. تصمیم نهایی محل اجرا و معماری به تایید کاربر موکول است.
## برخورد با 8623
CTE محل ذخیره فیزیکی نیست؛ SQL Server ممکن است شاخه‌های تکراری را expand کند و فضای جستجوی optimizer بسیار بزرگ شود. MAXDOP درمان پیچیدگی compile نیست. از کوئری موفق قبلی فقط خروجی شناسه‌های مورد نیاز را بگیر؛ کوئری دوم بر پایه فهرست VALUES ثابت. برای closure چندبه‌چند به صورت مرحله‌ای گسترش به هر دو جهت تا ثابت شدن مجموعه؛ تحلیل خارج ERP. هیچ تغییر در ERP انجام نشود. اگر حتی نسخه قبلی سنگین شد، محدودسازی با سال/شناسه و اجرای مستقل.
